## Halo 插件数据库配置说明

在 **Halo 插件开发**中，**数据库配置是由 Halo 主应用统一管理的**，插件不需要单独配置数据库连接。

### 工作原理

1. **Halo 主应用管理数据源**：数据库连接（SQLite/MySQL/PostgreSQL）在 Halo 主应用的 `application.yaml` 中配置
2. **插件自动继承**：插件作为 Spring Bean 运行在 Halo 主应用的 Spring 容器中，会自动使用主应用的 DataSource
3. **JPA 自动建表**：使用 `@Entity` 注解的实体类会在首次使用时自动创建表

### 已创建的配置

### Halo 主应用数据库配置位置

如果你需要查看或修改数据库配置，需要在 **Halo 主应用**的配置文件中设置：

```yaml
# Halo 主应用 application.yaml
spring:
  datasource:
    url: jdbc:sqlite:./data/halo.db
    # 或 MySQL: jdbc:mysql://localhost:3306/halo?useSSL=false&serverTimezone=Asia/Shanghai
    # 或 PostgreSQL: jdbc:postgresql://localhost:5432/halo
    driver-class-name: org.sqlite.JDBC
    username: admin
    password: password
```

### 插件中无需配置的原因

- **安全性**：数据库密码等敏感信息不应放在插件中
- **统一性**：所有插件共享同一个数据源，避免连接池浪费
- **简化部署**：用户只需配置一次，所有插件自动使用

**Assistant**

这是 Halo 框架中的 **`@GVK` 注解**，用于定义**自定义内容类型（Custom Resource Definition，CRD）**。这是 Halo Content API 的核心概念，让插件可以定义自己的数据模型。

## `@GVK` 注解详解

### 含义说明

| 参数 | 值 | 说明 |
|------|-----|------|
| `group` | `moment.halo.run` | **资源组名**，类似于 Java 的包名，用于命名空间隔离，通常使用反向域名格式 |
| `version` | `v1alpha1` | **API 版本**，`alpha` 表示预览版，`beta` 表示测试版，`v1` 表示稳定版 |
| `kind` | `Moment` | **资源类型名称**，首字母大写，是资源的标识 |
| `plural` | `moments` | **复数形式**，用于 REST API 路径，如 `/apis/moment.halo.run/v1alpha1/moments` |
| `singular` | `moment` | **单数形式**，用于命令行工具或文档引用 |

### 工作原理

这是 Halo 借鉴 **Kubernetes CRD（自定义资源定义）** 的设计理念：

```
┌─────────────────────────────────────────────────────────────┐
│                    Halo Content API                        │
├─────────────────────────────────────────────────────────────┤
│  @GVK(group="moment.halo.run", version="v1alpha1", ...)   │
│                          │                                 │
│                          ▼                                 │
│  创建自定义资源类型 "Moment"                               │
│                          │                                 │
│                          ▼                                 │
│  自动生成 REST API:                                        │
│  GET    /apis/moment.halo.run/v1alpha1/moments            │
│  POST   /apis/moment.halo.run/v1alpha1/moments            │
│  GET    /apis/moment.halo.run/v1alpha1/moments/{name}     │
│  PUT    /apis/moment.halo.run/v1alpha1/moments/{name}     │
│  DELETE /apis/moment.halo.run/v1alpha1/moments/{name}     │
└─────────────────────────────────────────────────────────────┘
```

### 使用示例

通常与 `@Schema` 注解配合使用，定义完整的内容类型：

```java
@GVK(
    group = "moment.halo.run", 
    version = "v1alpha1", 
    kind = "Moment", 
    plural = "moments", 
    singular = "moment"
)
@Data
public class Moment {
    private String spec;
    private MomentStatus status;
    // ...
}
```

### 对比传统方式

| 方式 | 特点 | 适用场景 |
|------|------|----------|
| **`@GVK` + Content API** | 自动生成 REST API、支持版本管理、与 Halo 生态深度集成 | Halo 官方推荐方式，适合内容类插件 |
| **传统 Spring Controller** | 完全自定义、灵活控制 | 需要特殊业务逻辑的场景 |

### 你的插件选择

你的日记插件目前使用的是 **传统 Spring Controller** 方式（`@RestController` + `/api/diary`），这在 Halo 插件中也是完全合法的。

如果你想改为 Halo 官方推荐的方式，可以创建类似这样的类：

```java
@GVK(
    group = "diary.miany.run", 
    version = "v1alpha1", 
    kind = "Diary", 
    plural = "diaries", 
    singular = "diary"
)
public class Diary {
    private DiarySpec spec;
    private DiaryStatus status;
}
```

两种方式都可以工作，选择取决于你的需求复杂度和集成深度。
