Halo 插件的热重载是由 **Halo 框架自动处理的**，插件开发者不需要自己实现。热重载主要依赖以下机制：

## Halo 插件热重载原理

### 1. 自动检测机制
Halo 会监控插件目录（`~/.halo2/plugins/`）下的插件文件变化，当检测到 `.jar` 文件更新时，会自动：
- 停止旧版本插件（调用 `stop()` 方法）
- 加载新版本插件（调用 `start()` 方法）

### 2. 开发模式热重载
在开发阶段，你可以通过以下方式实现热重载：

**方式一：使用 Halo 提供的开发模式**
```bash
# 启动开发模式的 Halo
halo --halo.security.initializer.suppressor=anything
```

**方式二：直接重新打包**
```bash
./gradlew build
```
构建完成后，Halo 会自动检测并重载插件。

### 3. 插件生命周期
你的插件只需正确实现这两个方法即可：

```java
@Override
public void start() {
    // 插件启用时执行（如注册路由、Bean等）
}

@Override
public void stop() {
    // 插件停用时执行（清理资源）
}
```

### 4. 注意事项
- **保持状态可恢复**：热重载时会调用 `stop()` 再 `start()`，所以需要确保状态能正确保存和恢复
- **避免静态变量**：热重载可能导致类重新加载，静态变量会丢失
- **资源释放**：在 `stop()` 中释放所有资源（线程、连接等）

### 5. 前端资源热重载
你的 Vue 前端部分（`ui/` 目录）通过 `rsbuild` 开发服务器运行，修改 `ui/src/` 下的文件后会自动热更新（HRM），不需要重新构建。

---

**总结**：Halo 插件的热重载是框架内置的，你只需要确保 `start()` 和 `stop()` 方法正确实现即可。开发时用 `./gradlew build` 重新打包，Halo 会自动处理后续的重载。

- 代码会被压缩优化
- 供 `./gradlew build` 打包进 JAR

**总结**：开发时用 `dev`，部署时用 `build`。

## 构建流程

执行 `./gradlew build` 时：
1. 先执行 `:ui:pnpmBuild` → 编译前端代码到 `ui/build/dist`
2. 再执行 `:processUiResources` → 将前端资源复制到后端资源目录
3. 最后打包插件 JAR（包含前端资源）

这样设计可以让前后端独立开发，同时构建时自动整合在一起。
